# Web 稳定性

本文记录当前 Web 稳定性实现的请求、会话与错误处理边界。

## 请求与状态保护

- 普通请求和 AI 请求都使用 `AbortController` 与 Promise deadline 限制在 10 秒内完成；deadline 覆盖响应体读取与解析。
- P2P 状态轮询按 1200 毫秒周期运行；每次请求的单次 timeout 为 4 秒，并要读取、解析响应 body，再根据协议结果更新局面或连接状态。
- 请求结束时，无论成功、失败还是超时，都在 `finally` 中释放请求中标记，避免后续请求被永久挡住。
- 每个请求带有 owner 与会话 generation 保护，P2P 状态还检查 `state_version`；过期响应不能覆盖更新的局面。
- 返回菜单会立即撤销当前会话并停止相关 UI 工作；稍后完成的 leave 请求不能影响新游戏或新会话。
- AI 超时只做状态级重新同步，不立即再次调用 `ai_move`。客户端 timeout 只终止本地等待，不取消服务器已经开始的行动；手动同步只有在权威状态仍轮到 AI、`ai_thinking === false` 且没有进行中的 AI 请求时，才显示一次明确的安全重试入口。

## P2P 重试与终态

短暂网络错误使用有界退避重试，退避上限为 10 秒，并保留本地房间码和 `player_token`，以便在连接恢复后继续同一会话。终态协议错误 `invalid_token`、`room_expired`、`room_not_found` 会停止轮询、清理本地会话并返回重新加入流程；重试不会绕过这些终态。

页面显示给玩家的错误使用简体中文；机器协议码仍单独保留给分支判断和诊断，不能用显示文案替代协议码。`player_token` 不进入玩家文案或日志。

## 新手教程与跨线结果（2026-10-12）

- 普通主页首次访问会展示三课互动教程，菜单与对局顶部都可重开。练习使用独立引擎生成合法走子、后继棋盘与提交结果；`GET /api/tutorial` 不修改本地对局、P2P 房间或房间版本。
- 教程加载沿用请求超时与错误反馈，关闭后到达的旧响应会被忽略。存储不可用时仍可关闭。弹窗打开时，游戏快捷键不能误提交正在进行的行动。
- Web 与 P2P 的走子响应使用引擎实际记录的 Move，返回 `result_source_board` 和 `result_destination_board`。自动定位、高亮及曲线使用实际后继棋盘，历史分支使用新 Timeline ID。
- `submit_blocker` 区分尚有必须推进棋盘、王安全不满足、对局结束和只读模式。提交仍由权威引擎决定；客户端教程和文案不改变规则。
- 回归覆盖王离开后的无王棋盘仍能走子、同一棋盘上所有王的安全、跨线/分支到达位置、显式提交、教程隔离与请求竞态。浏览器已走完三课，并验证正常对局及中途打开/关闭教程后继续对局。
- 最终本地验证：614 项通过、2 项跳过；三组 Node 回归、源码编译和 JavaScript 语法检查均通过。大型局面的首次时限波动和复测结果保留在 `arena-acceptance-status.md`。

本地和 P2P 共用该字段；页面持续显示提醒，走子后随权威状态清除。无额外持久化计数器，存档恢复和模拟副本复用同一历史数据。浏览器已实测两轮马往返后提醒出现、改走兵后消失，且始终可继续提交。

## 规划超时修复（2026-10-12 后续）

生产模式的单步探测现在会提前跳过无法一次推进所有必走棋盘的非分支走法，把探测时间留给可能完成行动的历史分支。这些普通走法仍保留在多步搜索中，棋规、模型和 5 秒 / 1024 状态 / 24 候选预算均未改变。

新抓取的种子 54 局面（8 条时间线、8 张必走棋盘）在修复前稳定耗尽 5 秒且没有候选；修复后同一局面约 0.61 秒得到 24 个可合法提交的候选。完整回归 **649 项通过、2 项跳过**；简单 20 局、中等 4 局、困难 4 局共 1398 个行动，规划失败、备用恢复、非法行动、过期状态和意外异常均为零，最多发展到 24 条时间线。终局评估仍可能给出安全上限提示，其计数与规划失败分开保存。

原先种子 53 的 21 条时间线失败没有保存完整局面，因此不宣称对它做了完全相同局面的回放。本轮保留了新的超时存档和所有候选的合法性回归；种子 53、54 的长局复测均正常结束。详细前后对比和每局证据见 [超时修复验证记录](planner-timeout-fix-20261012.json)。

## AI 往返偏好（2026-10-12 后续）

往返提醒现在也用于 AI 选招。Planner 可按需读取已提交历史，为已经验证的完整候选行动附上重复标记；直接复用候选叶节点，不额外重放或执行终局搜索。统计窗口包含候选提交在内的最近 64 个行动，第三次相同前沿配置才触发偏好；历史扫描计入原有规划时限。合法走法集合、分支规则、失败状态缓存和判和规则均不受影响。

简单档在有其他候选时随机选择不会触发重复的行动；全部候选都重复时仍正常选招。中等和困难档只在根节点为重复候选扣除 0.25 个兵的评价分，并相应调整 alpha 界限；明显更优的重复走法仍可被选中。神经网络档使用 `log(1.1)` 的小幅 logit 扣分，保留原始输出、模型权重和对外报告的分数。该偏好不能保证消除所有循环，尤其在候选集合受限、重复走法优势明显或不得不重复时。

新增回归覆盖多时间线完整配置、分支隔离、近似同分时换招、优势/唯一重复候选、搜索时限和原超时存档。完整回归 **672 项通过、2 项跳过**。简单 4 局、中等 4 局、困难 20 局共 1079 个行动，规划失败、备用恢复、非法行动、过期状态、意外异常和完整前沿重复提醒均为零；最多 24 条时间线。另有 2 局达到 120 行动的测试上限，简单档有 3 次终局评估安全提示，不能据此宣称所有长局或单个棋子的往返都已消除。模型、预算和验证期间源码哈希保持不变，修改仍在本地。完整结果见 [本轮验证记录](ai-repetition-validation-20261012.json) 和 `arena-acceptance-status.md`。

## AI 终局评分修正（2026-10-12 后续）

中等和困难档现在优先读取已经确认的终局，再检查深度和时间限制；将死按胜负评分，逼和/和棋为零。搜索证明无合法行动时复用规范终局分类，未完成搜索仍按普通局面评分。原来会主动逼和、忽略一步将死或贪吃兵后被将死的错误已加入回归。

与 `8989fce5` 相同预算的 16 次战术决策相比，立即将死从 **6/16 提升至 16/16**；两个可复现败局均改为能防住下一步将死的走法，并穷举对方合法行动确认。该结果只证明这些具体战术有改善，不代表通用胜率或等级分提升，也没有重新训练神经网络。见 [对照验证记录](ai-terminal-scoring-validation-20261012.json)。

远端 CI 首轮另发现 23 张必走棋盘的历史局面在较慢机器上仍可能超时。随后减少同一次王安全查询中重复的空间上不可能攻击的比较，保留目标顺序、真实时空位移和路径检查；不缓存可变棋盘、不增加预算。完整几何枚举与历史局面的威胁列表对照验证其等价性。

本轮最终全量回归 **730 项通过、2 项跳过**，编译和三组 Node 回归通过。重启后的中等人机对局已实测完成玩家提交、AI 回应和回到玩家行动。GitHub 工作流的两行教程检查补丁因当前 OAuth 凭据缺少 `workflow` 权限留在本地；应用代码和测试通过现有 CI 验证，远端运行结果按具体提交另行记录。
