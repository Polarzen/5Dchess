## 自动回归

`tests/test_saved_replay.py` 验证：多时间线、同一行动多步走子的回放顺序与提交边界；前进、后退、跳转后的精确局面；回放不写文件；续局读取最终存档；实际将杀棋局只能回放；空棋局不会自动播放循环；损坏或不可重建的存档不替换当前会话；在线房间保护；22 份存档完整列出；重复播放请求不跳步，手动操作暂停播放。

该文件还在独立 Python 进程中阻止 `mysql`、`sqlalchemy` 导入及所有 socket 连接，并设置无效 `DB_PORT`，验证主程序导入、Web 首页、存档列表与回放均可运行。

`tests/test_p2p_persistence.py` 的本机权限矩阵覆盖新增回放入口。`tests/test_browser_reliability.js` 覆盖续局与回放互斥、结束棋局的按钮状态、过期响应和播放定时器隔离、请求失败暂停、步数范围检查、终局回放不弹出阻挡操作的结束层。

## 实际页面操作

使用独立存档目录和仅监听 127.0.0.1 的测试服务，在浏览器中：

1. 打开“存档与回放”，确认同一存档具有“继续对局”和“观看回放”两个入口。
2. 从第 0 手开始，第一手仍为白方且未提交；第二手提交行动并切换黑方。
3. 面板输入步数 1 并跳转，显示第 1 / 2 手；点击播放后到第 2 / 2 手自动停止。
4. 返回菜单，用同一份存档继续对局，得到新房间码与原最终局面。

旧的浏览器 `prompt()` 跳转在内置浏览器中不可用，已替换成面板内输入框。页面验证服务和临时标签页在验收后关闭。

## 长局追加验证（2026-10-12）

详见 [机器可读记录](ai-replay-validation-20261012.json)。从 118 个行动、122 步、9 条时间线的历史局面开始，双方使用困难 AI，新增 22 个已提交行动，达到 140 个行动、169 步、18 条时间线、1172 个棋盘。每个新增行动均保存、恢复并执行相同计划，比对完整状态。

逐步重建独立参考局面，验证全部前进、后退、随机跳转，以及 HTTP 回放和续局；回放前后文件字节不变。144 步存档的 HTTP 加载从 12.64 秒降到 3.00 秒；169 步存档加载 5.89 秒，抽样 HTTP 跳转最高 0.057 秒，续局 0.25 秒。时间来自本机 Flask 测试客户端，不含网络和浏览器渲染。

长局测试修复了数字键排序导致存档校验失败的问题，并兼容旧校验编码。回放通过验证后续完整行动来证明历史局面非终局，保留最终终局检查；不符合当前单步规则的旧棋谱不能充当证明，会退回原先的完整终局检查。

18 条时间线局面的下一次困难 AI 搜索仍可能耗尽既有 5 秒预算，未把这种未知结果当作将杀。该局面保存在 `tests/fixtures/hard_replay_169_state.json.gz`，其截至最后已提交行动的存档与回放均验证通过。旧的 28 条时间线诊断档含无法通过当前王安全提交规则的历史行动，已按原规则拒绝回放，不列为成功样本。

后续搜索优化与这一失败边界的修复结果，见 [2026-10-13 验证记录](ai-search-efficiency-20261013.json)。上段保留 10 月 12 日原始验收状态。
