## 存档调查

对反馈的 15 手、10 次提交、4 条时间线存档完成校验和验证与严格回放，最终局面可精确重建，结果为白方被将杀。原始存档、保存时间、标识符及个人文件路径不放入仓库；回归测试只使用匿名走子坐标。

- 第 5 手之后，黑方必须推进 L0、L+1，同时也允许在更早的 L+2 最新棋盘走子。L+2 不参与当前时刻，但并未禁止操作。
- 在 L+2 推进黑方棋盘并完成其他必须推进的棋盘后，白方可以再次移动先前跳入该支线的马。
- 第 13 手跨历史吃象后，象仅在新支线 L+3 的后继中被马替换；L0 的历史和后续仍保留象。这符合分支规则，不是吃子未生效。
- 本次不改变活动线、轮到谁、历史保存或将杀规则。界面补充全部可操作棋盘的定位入口、可选支线状态、历史棋盘跳到最新局面、等待对手和已将杀的明确原因。

- Cloudflare 准备失败或隧道连接失败时，保留网站并生成手动命令；未连通的自动隧道会停止。支持标准输出与错误输出合并识别就绪，仍要求分配网址和注册连接都完成，不将申请接口网址误当公网入口。

## 本机实际验证

- 浏览器从第 5 手局面开始，导航到 L+2 / T0 黑方，选择兵并落子成功，生成 L+2 / T1 白方；“当前行动”列表相应减少已推进的棋盘。
- 历史棋盘可定位到本线最新棋盘；1280 × 900、390 × 844 布局核对通过，手机文档宽度为 390，无新增页面横向溢出，控制台错误为 0。
- 复现 Windows 普通 wildcard bind 漏检现有 loopback 网站的问题；增加独占地址探测后，从被占用的 5275 切换到 5276。手动连接模式的两种命令均使用实际端口。
- 实际页面 HTTP 200，按 Ctrl+C 后网站停止、5276 监听释放；没有停止占用 5275 的测试网站。

本次未进行异地双机验收，也没有将模拟隧道成功视为公网实际连通。反馈者尚未提供成功的 CMD 完整命令和程序版本，因此无法断言之前的公网失败来自哪一个具体差异。新版提供协议、程序来源和手动连接选择，保留日志供后续对比。
