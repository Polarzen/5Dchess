# 浅粉色界面与交互性能

2026-10-13，本地 Windows / Python 3.11 验证。

## 界面

- 大厅采用浅粉、奶油白和深梅色，配有项目自制的 CSS 棋盘与 SVG 时间轨道插画。没有远程字体、图片或动画库请求。
- 棋盘、侧栏、13 课教程、存档、回放、房间码弹窗和终局提示使用同一套浅色主题。必须推进、合法落点、当前时刻分别保留独立颜色及文字提示。
- 点击棋子立即显示读取落点的状态；提交期间禁用重复提交。只有服务器接受的走子才更新棋盘，并播放短暂的棋盘淡入和到达反馈；不等待动效完成才继续操作。
- 支持键盘选格、按钮焦点和系统“减少动态效果”。在按钮或格子上按 Enter，不会额外触发全局回合提交快捷键。
- 手机下的对局面板横向排列，内容可单独滚动，保留定位、重新同步、房间码及执棋身份提示。

## 性能与协议

棋盘以坐标为键缓存 DOM。切换选择时更新发生变化的棋盘，历史棋盘和格子复用；目标落点先按棋盘、格子建立索引，避免逐格扫描整份走法。状态模型由服务器返回的新快照替换，不能原地修改棋盘对象。新局或退出后重新进入会通过会话代次清空渲染缓存。

客户端定时轮询 `/api/p2p/state` 增加可选的整数 `known_version`。认证和租约更新完成后，如果版本相同，服务器返回 `unchanged: true`、模式/身份及 `p2p` 连接元数据，跳过棋盘序列化；版本不同则返回完整棋局。未传版本、无效类型、显式“重新同步”和旧客户端仍获取完整状态。

前端只在房间、会话和当前版本完全匹配时接受精简响应，保留棋盘、选择和合法落点。走子、提交、对手离线或重连都会改变版本，触发完整同步。轮询间隔、超时、退避和身份保留期未增加。

一次真实开局响应测量（未压缩 JSON，无第二位玩家）：完整状态 **2,538 字节**，精简状态 **483 字节**，减少 **81.0%**。这个比例不等于真实公网延迟下降比例；有变化的状态仍会包含完整历史，落点首次未命中预取缓存时仍需等待服务器与网络。

## 设计参考

- [web.dev：高性能 CSS 动画](https://web.dev/articles/animations-guide)：短动效只使用透明度和变换，不在棋盘上持续动画布局、阴影或模糊。
- [web.dev：优化交互响应](https://web.dev/articles/optimize-inp)：提供即时反馈，减少不必要的 DOM 工作。
- [MDN：prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion)：CSS 和脚本动画同时尊重系统偏好。
